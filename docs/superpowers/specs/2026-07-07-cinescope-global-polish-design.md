# CineScope Global Polish Design

## 背景

截图暴露的问题不是单点 UI：默认候选池缺动漫、豆瓣探索接口风控时静默返回空、样例候选缺封面、Hero 不按分类变化、同步页和口味页没有同等视觉打磨、图片代理和本机代理教程不清晰。

## 设计目标

- 电影、电视剧、动漫都必须是一等分类；没有外网候选时，也要用本地高分精选池补齐。
- Hero 必须按当前分类取片：电影页轮播电影，电视剧页轮播电视剧，动漫页轮播动漫。
- 海报加载优先走本地 `/api/image-proxy`，失败后使用本地 SVG 标题海报，页面不能出现浏览器破图图标。
- 豆瓣探索接口返回风控 JSON 时不能假装成功，必须记录失败并提前回落到本地精选池。
- 详情页从普通信息抽屉升级为媒体详情页，包含剧情、元数据、演职员胶片带、推荐理由和风险提示。
- Clash / V2Ray 只配置本机 HTTP 代理端口；不要粘贴订阅地址，也不把订阅地址写入项目。

## 数据策略

- 新增 `curated_catalog.py`，维护无 Cookie、无商业 API key 的本地高分候选池。
- `backfill_missing_media_types()` 默认把请求的电影 / 电视剧 / 动漫补到每类至少 10 部。
- 豆瓣详情补全优先访问移动端 `https://m.douban.com/movie/subject/<id>/`，因为它更容易返回 `og:image` 和简介。
- 豆瓣探索接口连续风控失败时早停，避免推荐生成卡很久。

## UI 策略

- 全站统一 `homepage-studio` 视觉层：同步、口味、推荐、详情都使用同一套玻璃面板、胶片轨道和口味 DNA。
- 推荐区新增 `categorySpotlight` / `renderHeroCarousel`，按当前 tab 的 `spotlightPool()` 生成焦点轮播。
- 详情抽屉新增 `peopleCarousel()`，演职员以横向人物卡展示，并支持点击人物筛选相关作品。
- 同步页新增 `imageResilienceGuide()`，提供本机代理环境变量教程。

## 验收标准

- 默认无外部候选时仍出现电影、电视剧、动漫推荐。
- 动漫分类不为空。
- 分类 Hero 会随 tab 切换而变化。
- 视觉烟测中破图数量为 0。
- Cookie 和代理订阅地址不保存、不回显、不写入文档。
- 全量 `unittest` 通过。
